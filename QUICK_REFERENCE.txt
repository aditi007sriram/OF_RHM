🔄 PACKET FLOW (How It Works)
───────────────────────────────────────────────────────────────────────────────

  OUTGOING (Host → Internet):
  h1 app: "Send to 8.8.8.8"
  h1 kernel: SRC=10.0.0.1, DST=8.8.8.8
  SWITCH (T_OUT table): SRC=10.0.0.1 → REWRITE TO → 172.16.42.99
  Internet sees: SRC=172.16.42.99, DST=8.8.8.8 ✅

  INCOMING (Internet → Host):
  Google: SRC=8.8.8.8, DST=172.16.42.99 (the VIP!)
  SWITCH (T_IN table): DST=172.16.42.99 → REWRITE TO → 10.0.0.1
  h1 app: Gets response from 8.8.8.8 ✅ (doesn't know about VIPs)

🎓 KEY CONCEPTS
───────────────────────────────────────────────────────────────────────────────

  OPENFLOW:
    Protocol between switch and controller
    Switch = dumb (just follows orders)
    Controller = smart (decides what to do)
    Port 6653 = OpenFlow communication

  MININET:
    Virtual network simulator
    No real hardware needed
    Each host is a Linux namespace
    Can run real tools: ping, nmap, iperf, etc.

  RYU:
    OpenFlow controller framework (Python)
    Manages the switch behavior
    Implements MTD logic (VIP assignment, rotation)

  VIP (Virtual IP):
    Temporary IP address generated randomly
    Range: 172.16.0.0/16 (65,534 possible addresses)
    Every host gets one, every 30 seconds it changes

  FLOW TABLE:
    T_OUT: Outgoing traffic rewriting
    T_IN: Incoming traffic rewriting
    T_L2: Forwarding rules


⚠️ ATTACK DETECTION
